## 简介
Ping-X 是一个跨平台网络协议联通检测工具，支持 TCP、UDP、组播（Multicast）和 SSM（Source Specific Multicast）等多种协议的连通性测试。本快速开始指南将帮助你完成安装与首次使用，涵盖从源码编译与二进制下载两种方式、基础使用示例、YAML 配置文件示例、常用命令行标志说明，以及常见问题排查建议。

## 协议详解与示例

### TCP 协议
TCP 协议提供可靠的双向通信测试，支持 RTT 测量和丢包统计。

**发送端特性：**
- 建立 TCP 连接进行双向通信
- 支持 RTT（往返时间）测量
- 自动丢包检测和统计
- 可配置超时时间和包大小

**接收端特性：**
- 监听指定端口等待连接
- 接收探测包并自动回复确认
- 显示连接建立和断开信息

**使用示例：**
```bash
# 发送端：向目标主机发送 TCP 探测包
ping-x send -p tcp -t 192.168.1.100 -n 100 -i 1s -s 64

# 接收端：监听指定端口
ping-x recv -p tcp -p 9000
```

### UDP 协议
UDP 协议提供无连接的单向通信测试，适合快速连通性检测。

**发送端特性：**
- UDP 数据报发送
- 支持超时等待响应
- 自动丢包检测
- 可配置目标端口和包大小

**接收端特性：**
- 监听指定端口接收数据报
- 接收探测包并自动回复确认
- 支持多播组接收

**使用示例：**
```bash
# 发送端：向目标主机发送 UDP 探测包
ping-x send -p udp -t 192.168.1.100 -n 50 -i 1s

# 接收端：监听指定端口
ping-x recv -p udp -p 9001
```

### 组播（Multicast）协议
组播协议支持一对多的数据传输，适用于网络设备发现和广播测试。

**发送端特性：**
- 向多播组地址发送数据包
- 支持设置 TTL（生存时间）
- 可配置网络接口
- 单向发送，不等待确认

**接收端特性：**
- 加入多播组进行接收
- 支持指定网络接口
- 显示组播包接收信息
- 支持多播组离开

**使用示例：**
```bash
# 发送端：向多播组发送数据包
ping-x send -p multicast -g 239.1.1.1 -n 20 -i 1s -e eth0

# 接收端：加入多播组监听
ping-x recv -p multicast -g 239.1.1.1 -p 9002 -e eth0
```

### SSM（Source Specific Multicast）协议
SSM 协议支持指定源的多播通信，提供更精确的多播控制。

**发送端特性：**
- 向指定源的多播组发送数据包
- 支持绑定特定源地址
- 支持设置 TTL 和网络接口
- 单向发送，不等待确认

**接收端特性：**
- 加入指定源的多播组
- 支持不同平台的 SSM 实现
- 显示源地址信息
- 支持多播组离开

**使用示例：**
```bash
# 发送端：向指定源的多播组发送数据包
ping-x send -p ssm -g 232.1.1.1 -b 10.0.0.50 -n 20 -i 1s -e eth0

# 接收端：加入指定源的多播组
ping-x recv -p ssm -g 232.1.1.1 -s 10.0.0.50 -p 9003 -e eth0
```

## YAML 配置文件示例

以下示例展示了如何配置所有四种协议的发送与接收任务。请将以下内容保存为 YAML 文件并在运行时通过 --config 指定。

```yaml
# ping-x 示例配置文件
# 每个测试定义一个探测任务，分别在 sender 和 receiver 端运行对应 mode 的配置

tests:
  # TCP 基础测试
  - name: "tcp-basic"
    proto: tcp
    mode: send
    target: 192.168.1.100
    port: 9000
    count: 100
    interval: 1s
    timeout: 3s
    size: 64

  - name: "tcp-basic-recv"
    proto: tcp
    mode: recv
    port: 9000

  # UDP 测试
  - name: "udp-test"
    proto: udp
    mode: send
    target: 192.168.1.100
    port: 9001
    count: 50
    interval: 1s

  - name: "udp-test-recv"
    proto: udp
    mode: recv
    port: 9001

  # 组播测试
  - name: "multicast-group1"
    proto: multicast
    mode: recv
    group: 239.1.1.1
    port: 9002
    iface: eth0

  - name: "multicast-group1-send"
    proto: multicast
    mode: send
    group: 239.1.1.1
    port: 9002
    iface: eth0
    count: 20

  # SSM 测试
  - name: "ssm-source1"
    proto: ssm
    mode: recv
    group: 232.1.1.1
    source: 10.0.0.50
    port: 9003
    iface: eth0

  - name: "ssm-source1-send"
    proto: ssm
    mode: send
    group: 232.1.1.1
    port: 9003
    iface: eth0
    bind: 10.0.0.50
    count: 20
```

**字段说明：**
- `name`: 测试任务名称
- `proto`: 协议类型（tcp/udp/multicast/ssm）
- `mode`: 模式（send/recv）
- `target`: 目标地址（tcp/udp 必填）
- `group`: 多播组地址（multicast/ssm 必填）
- `source`: SSM 源地址（ssm 必填）
- `port`: 端口（必填）
- `bind`: 本地绑定地址
- `iface`: 网络接口名（多播时使用）
- `count`: 发送次数（0=持续发送）
- `interval`: 发送间隔
- `timeout`: 单包超时时间
- `size`: 探测包大小（字节）
- `ttl`: TTL（0=自动选择）

## 常用命令行标志说明

### 根命令标志
- `--config/-c`: 指定配置文件路径（可选）
- `--verbose/-v`: 启用详细输出模式（可选）

### 发送模式（send）标志
- `--proto/-p`: 协议类型（tcp/udp/multicast/ssm，默认: tcp）
- `--target/-t`: 目标地址（tcp/udp 必填）
- `--group/-g`: 多播组地址（multicast/ssm 必填）
- `--port`: 目标端口（必填）
- `--bind/-b`: 本地绑定地址（默认: 0.0.0.0）
- `--iface/-i`: 网络接口名（多播时使用）
- `--count/-n`: 发送次数（0=持续发送）
- `--interval`: 发送间隔（默认: 1s）
- `--timeout`: 单包超时时间（默认: 3s）
- `--size/-s`: 探测包大小（字节，默认: 64）
- `--ttl`: TTL（0=自动选择: unicast=64, multicast=16）

### 接收模式（recv）标志
- `--proto/-p`: 协议类型（tcp/udp/multicast/ssm，默认: tcp）
- `--bind/-b`: 监听绑定地址（默认: 0.0.0.0）
- `--port`: 监听端口（必填）
- `--group/-g`: 多播组地址（multicast/ssm 必填）
- `--source`: SSM 源地址（ssm 必填）
- `--iface/-i`: 网络接口名（多播时使用）

- **配置校验失败**：

### 网络连接问题
- **TCP 连接失败**：

  - 处理：检查目标主机和端口可达性，确认防火墙设置

- **UDP 发送失败**：

- **多播加入失败**：
  - 现象：无法加入多播组或指定网络接口

### 权限和安全问题

## 性能考虑

### 发送参数优化
- **发送间隔与超时**：合理设置间隔与超时可平衡探测频率与资源占用
- **包大小**：增大包大小会增加带宽占用，建议按实际网络环境调整
- **发送次数**：合理设置 count 参数避免过度网络负载

### 多播性能优化
- **TTL 设置**：对于多播场景，TTL 影响数据包传播范围，建议按网络拓扑选择合适值
- **网络接口**：指定正确的网络接口可提高多播性能
- **组播组管理**：合理管理多播组加入和离开操作

### 平台差异考虑
- **SSM 实现差异**：不同操作系统对 SSM 的支持程度不同，需要相应的平台特定实现
- **网络栈差异**：不同操作系统的网络栈行为可能影响测试结果
